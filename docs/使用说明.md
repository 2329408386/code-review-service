# XKL 代码检视平台 · 使用说明

平台地址：<http://10.21.48.65:8083>

代码仓接入后（见《接入指南》），每次创建或更新合并请求（MR），平台会自动用大模型检视本次新增的代码，并给出检视意见和 MR 整体评价。本文介绍如何在平台上查看结果，以及如何在 CodeHub 上处理检视意见。

查看平台不需要登录。

---

## 1. 页面概览

左侧导航有以下页面：

| 页面 | 用途 |
|---|---|
| **检视记录** | 查看每一次检视的状态、意见和推理过程（最常用） |
| **数据统计** | 按时间、分组、代码仓查看检视量、意见构成、Token 消耗和模型情况 |
| **代码仓** | 查看所有代码仓的检视次数、所属分组 |
| **模型路由** | 查看各代码仓使用的模型 |
| **检视范围** | 查看各代码仓只检视哪些目标分支 |

左下角显示服务状态：绿点表示服务正常。

## 2. 检视记录

### 2.1 顶部指标

- **检视记录**：符合当前筛选条件的检视次数，下方显示排队中和执行中的任务数。
- **检视意见**：意见总数，右侧的小环形图是开发者回复的分布（已解决 / 没问题 / 无风险 / 其他）。
- **代码仓**：涉及的代码仓数量。

### 2.2 筛选与排序

- **搜索代码仓 / 搜索提交人**：输入关键字自动筛选，按回车立即搜索。
- **状态**：全部、排队中、检视中、已完成、失败、已忽略。
- **排序**：最新在前 / 最早在前。
- **展示方式**：按时间平铺，或按代码仓分组展示。
- **每页数量**：30 / 60 / 120 / 240 条。

筛选条件会保存在浏览器里，刷新页面后仍然保留。

### 2.3 检视卡片

每张卡片是一次检视，显示状态、意见条数、MR 标题、代码仓与 MR 编号、提交人和时间。鼠标悬停可以看到完整标题和分支信息。

| 状态 | 含义 |
|---|---|
| 排队中 | 等待检视 |
| 检视中 | 模型正在检视 |
| 已完成 | 检视完成，可查看意见 |
| 失败 | 检视过程出错，可在详情中查看原因 |
| 已忽略 | 不需要检视（如目标分支不在检视范围、改动过大），详情中有原因 |

页面顶部单独列出的「**晚上8点后检视**」分组，是改动较大、被安排到当天 20:00（北京时间）之后执行的 MR，到点会自动检视。

### 2.4 检视详情

点击卡片打开右侧详情，有三个标签页：

**概览**

任务信息（触发动作、检视模式、创建与开始时间、耗时、检视分片数、检视文件数与新增行数、有效 / 被过滤的意见数、使用的模型、Token 用量、源提交与目标提交），以及检视总结、MR 整体评价和 MR 描述。失败或已忽略时会显示原因。

**检视意见**

列出每条意见：严重级别、文件路径与行号、标题和详细说明，以及该意见在 CodeHub 上的发表状态（已回写 / 待回写 / 回写失败等）。点击「**导出 CSV**」可以下载全部意见。

意见的严重级别：

| 级别 | 含义 |
|---|---|
| 严重 | 很可能导致缺陷、安全问题或数据错误，建议合入前修复 |
| 一般 | 存在问题或隐患，建议修复 |
| 建议 | 可读性、可维护性等方面的改进建议 |

**推理过程**

模型检视时的思考与操作记录，按检视分片分组（大 MR 会拆成多个分片并行检视）。其中每一步「推理步骤」带有编号 1、2、3……，便于对照阅读；「命令执行」「提示」等辅助记录不编号。点击某一条可展开完整内容，也可以「全部展开 / 全部收起」。检视进行中时，推理过程会实时刷新。

## 3. 在 CodeHub 上处理检视意见

如果代码仓已开通意见发表（见《接入指南》的可选部分），意见会以行内评论的形式出现在 MR 对应的代码行上，格式为：

```
【严重】标题：详细说明
```

首次创建 MR 时，平台还会发表一条 **MR 整体评价**：1～5 分（意见越多、越严重，分数越低）和两点简短评价。

### 回复意见

请直接在评论下回复，平台会自动识别你的回复并统计：

| 回复中包含 | 统计为 |
|---|---|
| 没问题 | 没问题 |
| 确认、已解决 | 已解决 |
| 无风险 | 无风险 |
| 其他内容 | 其他 |

回复中包含 **解决、无风险、确认、没问题** 任一关键词时，平台会 **自动把该讨论置为「已解决」**。

没有任何回复的意见，统计时默认算作「已解决」。

## 4. 数据统计

### 4.1 筛选

- **时间范围**：近 7 天 / 近 30 天 / 近 90 天 / 全部（按北京时间的自然日计算）。
- **统计维度**：全部代码仓、某个分组、未分组，或某个代码仓。

选择会保存在浏览器里。在下方表格中点击分组名或代码仓名，也可以直接切换到它的统计。

### 4.2 内容

- **指标卡**：检视次数（含 MR 数和已忽略数）、检视意见（含平均每次条数）、成功率、代码仓数、总 Token、平均每次 Token（含平均耗时）。
- **检视趋势**：每天的检视次数和意见数，鼠标悬停查看当天明细。
- **意见构成**：严重级别分布和开发者回复分布两个环形图。
- **按分组**：各分组的检视、意见、已解决率和 Token 消耗（选择「全部代码仓」时显示）。
- **代码仓明细**：每个代码仓的检视次数、意见数、严重 / 一般 / 建议、已解决率、输入 / 输出 / 合计 Token。点击列头可以排序。
- **模型**：每个模型的调用次数、成功率、参与检视次数、产出意见数、Token 和平均耗时，以及 Token 占比。

## 6. 常见问题

**MR 提交后多久出结果？**

通常几分钟内完成，改动越大耗时越长。排队中的任务会依次执行。较大的 MR 白天提交时会安排到 20:00 之后。

**MR 更新（再次推送）后会重新检视吗？**

会。每次推送新的提交都会检视新的改动；MR 整体评价只在首次创建 MR 时发表一次。

**检视失败怎么办？**

在详情的「概览」中查看失败原因。多数是模型服务临时不可用，可以联系管理员重新检视。

**意见没有出现在 CodeHub 上？**

检查代码仓是否已开通意见发表（见《接入指南》可选部分）。在详情的「检视意见」中可以看到每条意见的发表状态和失败原因。
